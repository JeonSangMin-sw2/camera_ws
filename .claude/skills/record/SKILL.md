# 노션 기록 정리 절차
> **AI는 노션을 스스로 갱신하지 않는다.** 사용자가 정리를 요청할 때만 아래 절차대로 기록한다.
> 작업 중 상태는 저장소 안의 **로컬 진행 파일**(`docs/progress.md`)에 갱신한다. 세션이 끊겨도 이 파일로 이어서 작업하고, 노션 정리 때 이 파일을 근거로 쓴다.

## 정리 절차 (사용자가 요청했을 때)
1. **수집**: 마지막 노션 기록 이후의 작업을 모은다 (로컬 진행 파일, 대화의 결과 보고, git 변경 내역, 결과 파일).
2. **process(아카이브) — 진행 기록**: 작업과 문제를 시간순 표(Time / State / Context / Problem / Solution)에 한 행씩 추가한다. 검증 수준과 커밋은 Solution 끝에 붙인다. 기존 행의 상태가 바뀌면(미해결 → 해결) 그 행을 고치지 않고 새 행을 추가한다.
3. **process(아카이브) — 현황**: 현재 단계, 재개 지점, 일정, 남은 과제·결정 대기를 갱신한다.
4. **해당 시 갱신**: 아래 표에 따라 report, detail, harness, cps.
5. **보고**: 노션에서 무엇을 바꿨는지 사용자에게 요약한다.

## 무엇이 바뀌면 어디를 갱신하나
| 발생한 일 | 갱신할 페이지 |
|---|---|
| 작업 완료 (검증 포함) | process: 진행 기록 표에 행 추가 (State: 완료) |
| 환경·빌드·장비 문제를 만났다 | process: 진행 기록 표에 행 추가 (State: 미해결 / 해결) |
| 현재 단계·핵심 수치·재개 지점이 바뀌었다 | process: 재개 지점, 남은 과제·결정 대기 |
| 설계 결정(문제와 해결)이 생겼다 | cps: 결정 기록 끝에 C번호 추가 |
| 문제 정의·목표 성능·구성 스펙·해결 방안이 생기거나 바뀌었다 | report: 1장 |
| 환경·라이브러리·아키텍처·알고리즘·명칭이 바뀌었다 | report: 2장 |
| 범위·요구사항·기능 구성·모델(수식)·검증 결과가 바뀌었다 | detail |
| 명령·권한·검증 명령·새 규칙·새 트랩이 생겼다 | harness (저장소 CLAUDE.md도 함께) |
| 여러 프로젝트에 통하는 새 교훈 | 이 공통 하네스 (사용자 승인 후) |
