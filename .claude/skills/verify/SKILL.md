# 검증 게이트
모든 변경은 아래 게이트를 해당하는 데까지 통과해야 합니다. 프로젝트 harness에는 게이트별 실제 명령을, report 1.2 목표 성능에는 G4·G5의 합격 기준을 적습니다.

| 게이트 | 내용 | 통과 기준 | 비고 |
|---|---|---|---|
| **G1 lint·구동 확인** | 문법·린트·타입 검사, 모든 모듈 import(구동 확인). 코드 수정 후 **자동 실행** | 오류 0 | 이것만 통과하면 ⚪ 수준. 싸고 결과가 항상 같아 묻지 않음 |
| **G2 자동 테스트** | 전체 테스트 스위트. 코드 수정 후 작업 단위가 끝나면 **묻지 않고 실행** (허용) | 통과/실패/오류/skip 네 숫자로 보고, 실패 0 | 외부 플러그인 간섭 차단 권장 `[rby1]` |
| **G3 회귀 테스트** | 고친 버그와 커버리지 0인 경로에 테스트 추가 | 수정 전 실패, 수정 후 통과 | 단락평가로 버그를 놓치는 스모크 테스트 주의 `[cam]` |
| **G4 통합·시뮬레이터** | 시뮬레이터·합성 입력·재생 데이터로 전 경로 실행 | 프로젝트가 정한 수치 기준 | 오프라인 테스트가 없는 경로는 필수 `[cam]` |
| **G5 실기·실사용** | 실제 하드웨어·사용자 환경 | 프로젝트가 정한 합격 기준 | **사용자 승인 후에만** 실행 |

## 실행 방법
- 코드를 수정하면 G1은 hook이 자동으로 돌린다. 실패하면 먼저 고친다.
- G2는 작업 단위가 끝나면 묻지 않고 `test-runner` 에이전트로 실행한다.
- G4는 시뮬레이터임이 확인되면(명령이 시뮬레이터를 지정) 묻지 않고 실행한다.
- 실물 로봇·장비를 움직이는 것(G5 포함)은 매번 사용자에게 허락을 구한다. 허락 판정은 hook이 한다.
- 검증 결과의 표기(❌⚪🟠🟢)와 보고는 `rules/verification.md`와 `report-result`를 따른다.
