# 코딩 원칙

## 기준을 낮춰서 통과시키지 않는다
> 임계값·허용 오차·보호 조건·속도 제한·반복 상한을 올려서 테스트나 수렴을 '통과'시키지 않는다. 정말 필요하면 사용자와 상의하고, 결정을 아카이브의 cps 기록에 남긴다. `[cam]` `[wbm]`

- 폴백이나 '한 번 통과하면 종료' 같은 느슨한 판정을 되살려 통과시키지 않는다. 판정은 단일 통과가 아니라 통계(평균의 표준오차 등)로 한다. `[cam]`
- 사용자 요청으로 정책을 바꾸더라도 기존의 엄격한 동작은 기본값으로 보존하고 새 동작은 옵션으로 추가한다. `[wbm]`
- 필요조건과 충분조건을 구분한다. 필요조건만 만족한 기능을 '된다'고 안내하지 않고 미완성으로 취급한다. `[cam]`

## 조용한 실패 금지
- 실패는 명시적인 오류나 경고로 드러낸다. 저장 실패, 중복 키 병합, 틀린 프레임의 계산을 조용히 넘기지 않는다. `[cam]`
- 계산한 상태값(예: `converged`)을 호출부에서 하드코딩하지 않는다. `[cam]`
- 불변식은 **런타임이 아니라 빌드·적재 시점에** 검사해 거부한다. 어긋난 모델, 빠진 파일, 모호한 지정은 실패시킨다. `[isaac]`
- 중단된 결과를 성공으로 취급하거나 자동 적용하지 않는다. 저장이 실패하면 다음 단계로 넘어가지 않고 이전 상태를 복원한다. `[cam]`
- 보정·평균화로 문제를 가리기 전에 **원래 측정값을 먼저 로그에 남긴다**. 보정 폭에는 안전 한도를 두고, 넘으면 적용하지 않고 경고한다. `[cam]`

## 데이터를 지어내지 않는다
- 누락된 값을 임의로 채우거나 만료된 데이터를 새 값처럼 쓰지 않는다. `[wbm]`
- 확인 전에는 이름·모델 버전·파일·기본값을 임의로 확정하지 않는다. 다른 프로젝트의 값은 '참고값'이지 확정값이 아니다. `[wbm]`
- 추론하기 전에 권위 있는 원천(제조사 SDK, 실행 중인 시스템의 모델)을 먼저 확인한다. `[isaac]` `[wbm]`
- 검증할 수 없는 전제(예: CAD와 실물이 같다)에 기대는 방법은 채택하지 않는다. `[cam]`

## 원본 보존
- 원본 입력 파일(URDF, 설정, 사용자 데이터)은 수정하지 않고 변환 결과만 별도로 출력한다. 낡은 산출물은 원본 해시로 판별한다. `[isaac]`
- 사용자가 제공한 로그·결과는 수정하기 전 상태를 먼저 보존한다. `[wbm]`
- 테스트·스크립트는 실제 결과 폴더를 덮어쓰지 않도록 임시 경로로 돌려 실행한다. `[cam]`

## 외부 코드·의존성
- 선택적 네이티브 의존성이 없어도 앱 전체가 죽지 않도록 폴백을 둔다. `[rby1]`
- 공식 체계는 포크하지 말고 확장 지점에 붙인다. `[isaac]`
- 패치 전에 영향 범위(호출처 전체 검색)를 확인하고, 정공법과 임시 해결을 구분해 보고한다. `[isaac]`

## 실패한 시도를 반복하지 않는다
- 되돌린 시도는 코드 주석에 사유를 남기고, 프로젝트 harness 트랩에 **재시도 금지**로 올리도록 사용자에게 제안한다. `[cam]`
- 수학적으로 불가능하다고 증명된 방향은 다시 시도하지 않는다. 기각한 가설은 가설 / 검증 / 결과로 정리한다. `[cam]`

## 기능은 소스에 직접 쓴다
- 문자열 치환으로 소스나 스타일 파일을 고치는 스크립트(`sed -i`, 파이썬 `replace` 등)로 기능을 구현하지 않는다. 그렇게 만든 기능은 스크립트가 안 돌면 사라지고, 로직이 어디 있는지 알 수 없게 된다.
- 기능은 실제 소스에 직접 쓴다. 일괄 변경이 정말 필요하면 먼저 사용자에게 묻는다.
