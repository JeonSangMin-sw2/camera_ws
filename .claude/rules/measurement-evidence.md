# 측정과 증거 규칙

## 처음 성공하면 끝낸다
- 측정이나 검증을 처음 한 번 해서 성공하면 거기서 끝낸다. 이 결과로 성능이나 성공률을 말하지 않는다.
- 아래 측정 규칙(최소 10회, 중앙값·범위·n/N)은 **심화 검증**에 적용한다. 심화 검증은 사용자가 허락했을 때만 한다.

## 테스트 파일 위치와 재사용
- 측정·검증 코드는 `tests/` 경로에 둔다.
- 이미 있는 기능 검증과 겹치면 새 파일을 만들지 않는다. 기존 테스트 파일을 고쳐서 범용으로 쓸 수 있는 테스트 파일이 되게 한다.

## 측정 규칙
> **단발 측정으로 성능이나 성공률을 말하지 않는다.** 최소 10회, 중앙값과 범위, 성공 n/N을 보고한다. 이 규칙이 없어서 한 페이즈에서 세 번 잘못된 결론을 낸 적이 있다. `[isaac]`

- 측정 전 불변식을 확인한다: 잔여 프로세스 0, 측정 대상이 실제로 활성. 결과가 이상하면 모델보다 **측정 환경을 먼저 의심**한다. `[isaac]`
- 워밍업은 측정과 분리한다. `[isaac]`
- 개선 효과는 **동일한 입력으로 전후 비교**하고, 개선이 없으면 제품 경로에 반영하지 않는다. `[wbm]`
- 측정의 종류를 구분한다. 예: 모델 단독 추론 시간 ≠ 전체 파이프라인 지연. `[wbm]`
- 합격 목표치는 측정 전에 report 1.2 목표 성능에 먼저 적어 두고, 첫 baseline 결과로 조정한다. `[wbm]`
- 성공 판정은 'ERROR가 없음'이 아니라 긍정 신호(예: `ready` 메시지)로 한다. 로그 메시지를 곧이곧대로 믿지 말고 양쪽 로그를 대조한다. `[isaac]`
- 부호·방향·수렴성은 추정하지 말고 실측으로 확인한다 (반복마다 잔차가 커지면 부호 반대). `[cam]`

## 증거 규칙
- 증거용 실행 도중에는 소스를 수정하지 않는다. 수정이 있었다면 그 실행은 증거에서 제외한다. `[cam]`
- 결과 파일 경로, 실행 명령, 환경 버전을 남긴다. 다른 사람이 다시 실행할 수 있어야 한다. `[wbm]`
- 분석 스크립트는 데이터셋만 바꾸면 그대로 재실행되게 만든다. `[cam]`
- 세션 종료 시 사라지는 임시 경로(`/tmp`, 스크래치패드)에 보존할 산출물을 두지 않는다. `[isaac]`
