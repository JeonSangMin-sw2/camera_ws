# 카메라 캘리브레이션 개발 기준

2026-09-10 노션 문서와 로컬 코드·데이터를 대조한 기준. 노션 원본은 변경하지 않았다.

## 실행 및 변경 원칙

- 분석 → 가설 → 해당 가설을 판별하는 1~2개 모듈 검증 → 제품 수정 순서로 진행한다. 현재 수정 전 테스트 2개는 실패 상태다.
- Step1의 v1.2 순서 `J5 → 브래킷 → J6 → J3`를 유지한다. 선행 단계의 수렴/품질을 확인한 뒤 다음 단계에 결과를 전달해야 한다. 숫자가 반환됐다는 이유만으로 성공으로 취급하지 않는다.
- J6 계산기의 절대 목표와 J5/J3의 상대 보정량을 구분한다. 반복기에서 잔차를 먼저 계산하고 잔차에 감쇠를 적용한다. 측정 잔차 대신 감쇠된 이동량으로 수렴을 판정하지 않는다.
- 마커 평균은 순방향 변환에서 위치 median, 회전 SVD로 수행하고 필요한 역변환은 마지막에 한다. 인식 성공과 자세 정확도는 별도로 평가한다.
- 축 부호는 명령 스윕 방향과 실제 관측 궤적을 함께 사용한다. 명목 FK 축만으로 실제 영점을 정답 처리하지 않는다.
- Head Tilt와 카메라의 같은 축 회전은 독립 기계 영점으로 단정하지 않는다. 게이지를 바꾸면 회전뿐 아니라 평행이동을 포함한 전체 SE(3) 관측 예측이 보존돼야 한다. 정면 명령 기준과 모터 홈을 구분한다.
- Step1.5 평면 잔차를 3D 재투영 오차로 명명하지 않는다. 실제 3D 관측과 모델 예측의 잔차, 독립 식별 여부를 구분해 기록한다.
- Step2의 카메라 XYZ는 필요할 때 물리적 바운드 내에서 추정한다. 이번 작업 시점에는 이미 `optimize_camera=True`이므로 과거의 동결 결함을 현재 문제로 반복 진단하지 않는다.
- 임의 L2 페널티로 영점을 0으로 끌어당기지 않는다. 독립 물리 기준 없는 Step1.5 값을 강한 앵커로 고정해 정답으로 만들지 않는다.
- 설정/소스/모델/관측의 실행 시점을 함께 기록한다. 다른 패스나 오전·오후 결과를 하나의 보정 상태로 섞지 않는다. 관측 로그의 실행 ID·시각·전체 관절 상태가 없으면 해당 인과 추론의 한계를 명시한다.
- 테스트는 `tests/`에서 관리한다. 백업은 테스트의 목적을 확인한 뒤 현재 API에 필요한 범위만 이식한다. 실물 연결 하네스와 순수 모듈 테스트를 구분한다.

## 노션의 상충·시점 차이

| 문서 내용 | 현재 해석 |
|---|---|
| Tilt-카메라 게이지와 정면 명령 영점 관리 | 물리 영점의 독립 식별과 구분하는 기준으로 채택 |
| Step1.5의 Tilt를 확정값으로 Step2에 강하게 앵커 | 독립 기준·SE(3) 일관성 확인 전에는 적용하지 않음. 같은 문서의 게이지/L2 금지 지침과 충돌 |
| Head Tilt와 어깨 J0가 정확한 영공간 | 같은 방향 축만으로 정확한 영공간은 성립하지 않음. 기존 국소 자코비안 분석은 강한 부분 커플링을 보였음. 실제 오차 원인 확정과 구분 |
| Step1.5의 3D RMS 및 분리 성공 | 현재 제품 값은 두 평면 RMS의 조합, `decoupled=True` 상수. 실제 3D 정합 품질로 사용 불가 |
| Step2 카메라 XYZ 동결 | 과거 코드 진단. 현재 작업 트리에서는 이미 해제됨 |
| Python 3.10 고정 / 99개 테스트 통과 | 현재 실행 환경은 Python 3.11.9. 백업 당시의 결과이며 현재 환경·현재 코드 통과 증거가 아님 |
| D405 거리 약 500mm, J3 노이즈 ±0.08° | 이번 Step1 로그의 Z는 145.5~384.5mm. 노이즈 한계를 일반 상수로 가정하거나 임계값을 완화할 근거로 사용하지 않음 |
