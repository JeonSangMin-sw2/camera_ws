# Step1·Step1.5 수정 전 원인 분석

분석일: 2026-09-10. 기준: `b9efde9` + 작업 시작 시 존재하던 미커밋 변경. 이번 작업은 제품 수정 전 조사, 마커 통계 분석, 백업 테스트 검토 및 핵심 모듈 테스트 2개 작성/실행이다. 제품 코드·설정·원본 result·기존 scratch 스크립트는 수정하지 않았다. 로봇/카메라 연결 및 모션은 실행하지 않았다.

## 결론

**코드 결함 2개를 장비 없이 재현했다.** Step1 J6 반복기가 절대 목표에 감쇠를 적용해 목표에서 이탈한다. 현재 Step1.5는 틸트를 카메라 회전에 흡수하면서 평행이동은 CAD에 유지해 전체 3D 변환을 보존하지 못하고, 평면 잔차를 3D 잔차로 보고한다.

다만 이것만으로 실기체의 모든 오차가 설명됐거나 9월 2일 커밋이 직접 원인이라고 확정할 수 없다. **J6 반복기 결함은 9월 1일 코드에도 존재한다.** 최신 마커 관측에서는 큰 회전 급변이 과거 보고서보다 적어졌다. 인식 계층만의 문제로 몰아가거나 노이즈 임계값부터 완화할 근거는 부족하다.

## 입력 고정과 기존 보고서의 시점 차이

- 최신 NPZ는 `dataset_20260910_160530.npz`. 오전 10:05 및 오후 13:08 NPZ도 비교했다.
- 현재 Step1 텍스트는 **46블록, 7,864행**이다. 기존 `reports/real_result_20260910/report.md`의 42블록/6,452행은 이전 파일 내용 기준이다. 기존 보고서를 덮어쓰지 않았다.
- 분석 입력과 해당 시점의 소스·설정 59개 파일을 [snapshot](snapshot)에 복사했다. 해시는 [snapshot_manifest.json](snapshot_manifest.json), 이미 존재했던 수정은 [existing_changes.patch](existing_changes.patch)에 보관했다.
- 각 스윕 블록에는 고유 실행 ID·시각·전체 엔코더 상태가 없다. 동일 번호의 서로 다른 파일을 같은 패스로 묶어 FK 오프셋을 임의 재생하지 않았다. 현재 설정을 오전 데이터의 당시 설정으로 가정하지 않았다.
- 환경: Python 3.11.9, NumPy 2.4.6, SciPy 1.17.1. 노션의 Python 3.10 표기와 다르지만 이번 결함의 원인이라는 증거는 없다.

## 1. Step1: 절대 목표에 대한 감쇠 결함

위치: `core/calibration/JointCalibrator.py`, `perform_joint_calibration`, 약 266~283행.

현재 J6 계산기(`wrist_yaw2`, `wrist_roll_v13`)는 **절대 권장 오프셋**을 반환한다. 반복기는 그 절대값과 이전 상대 이동량의 부호를 비교한 뒤, 절대값에 감쇠를 곱하고 마지막에 현재 오프셋을 뺀다.

```text
현재:  이동량 = damping * absolute_target - current_offset
필요:  잔차   = absolute_target - current_offset
       이동량 = damping * 잔차
```

핵심 재현: 현재 오프셋 −2°, 측정기가 매번 정확한 절대 목표 −1°를 반환한다. 실제 제품 반복기를 호출했고 취득 함수만 일정한 측정으로 대체했다.

| 항목 | 결과 |
|---|---|
| 반복 시작 오프셋 | −2, −1, −0.8, −0.64, −0.512, −0.4096° |
| 반환값 | **−0.4164267°** |
| 정답 | **−1°** |
| 수렴 표시 | False, 6회 소진 후 평균 반환 |

첫 반복에서 이미 목표에 도착했는데, 다음 반복부터 목표를 0쪽으로 당긴다. 센서 노이즈·마커 검출·원 피팅과 무관한 반복기 결함이다.

같은 코드의 수렴 판정도 감쇠된 이동량에 의존하므로 실제 잔차가 큰데 이동량만 작아져 성공할 여지가 있다. 이 추가 경로는 정적 검토 결과이며 별도 테스트를 늘리지 않았다.

최신 오른쪽 J6 로그에서도 절대 목표 −0.143014°가 −0.114411°로 적용되는 감쇠 동작을 볼 수 있다. 다만 그 실물 측정은 반복마다 달라지므로 실제 최종 오프셋 오차를 위 인공 입력의 0.5836°로 간주하면 안 된다.

또한 Full Auto는 J5 결과의 존재만 확인하고 `converged=False`인 수치도 저장해 브래킷으로 진행할 수 있다(`main_ui.py`, 약 2121행). 노션의 선행 단계 수렴 조건과 다르며, 반복기 오류가 다음 단계로 전파될 경로다. 이번 두 검증 범위에서는 해당 UI 경로를 실행하지 않았다.

## 2. Step1.5: 회전만 바뀌는 게이지와 잘못된 품질 보고

위치: `core/calibration/HeadCameraCalibrator.py`, `_compute_head_camera_solution`, 약 369~435행.

현재 함수는 Pan/Tilt를 모두 0으로 반환하고 Pan/Tilt 평면 법선으로 카메라 회전을 구한다. Tilt 오차 h를 카메라 쪽으로 흡수하는 규약이라면 다음 전체 변환이 보존돼야 한다. 헤드의 Z-pan/Y-tilt가 교차하는 v1.2 URDF 기하를 기준으로 했다.

```text
원래: Rz(p) Ry(t + h) [R_cam, t_cam]
변경: Rz(p) Ry(t)     [Ry(h) R_cam, Ry(h) t_cam]
```

**회전뿐 아니라 카메라 위치도 `Ry(h) t_cam`이어야 한다.** 현재 반환은 회전에 h를 흡수하지만 위치는 `[0.047, 0.009, 0.057]m` 그대로다.

노이즈 없는 고정 마커에 Tilt −2°를 주입해 실제 솔버를 호출한 결과:

| 항목 | 결과 |
|---|---|
| 게이지 변환에 필요한 카메라 위치 | `[0.04498210, 0.009, 0.05860555]m` |
| 현재 반환 위치 | `[0.047, 0.009, 0.057]m` |
| 보정 결과로 복원한 고정 마커의 위치 산포 RMS | **0.309208mm** |
| 제품이 보고하는 `rmse_3d_marker_mm` | **0.0mm** |
| 제품이 보고하는 `decoupled` | **True** |

검증은 팔 FK의 정답을 가정하지 않는다. 복원한 마커 좌표가 모든 헤드 각도에서 한 점으로 모이는지만 검사한다. 0.01mm 기준은 무잡음 수치 검증용이며 D405의 실물 정확도 기준이 아니다.

`rmse_3d_marker_mm`은 실제 3D 예측 잔차가 아니라 `sqrt(tilt_plane_rms² + pan_plane_rms²)`다. `captured_tilt_angles`, `captured_pan_angles`는 계산에 사용되지 않는다. `decoupled=True`도 실제 식별 판정 없이 상수로 설정된다. 따라서 “평면이 잘 맞음”이 “물리 헤드 영점과 카메라가 분리됨”을 의미하지 않는다.

현재 구현을 물리적인 `mount_to_cam`의 독립 추정으로 설명하는 주석도 부정확하다. 독립 기계 기준 또는 관측 모델·게이지 규약을 먼저 명확히 해야 한다. 이번에 3D 변환 불일치는 확정했지만, 실기체의 실제 Tilt와 카메라 조립 각도를 독립적으로 결정한 것은 아니다.

## 3. 최신 마커 관측의 일관성

분석 도구: [analyze_calibration_results.py](../../tests/analyze_calibration_results.py). 상세 행·블록·해시: [marker_audit.json](marker_audit.json).

Step1은 46블록/7,864행 모두 수치가 유한하다. 단일 관절만 움직이고 카메라가 고정돼 있다는 조건에서, 인접 마커 회전각과 엔코더 회전량 크기를 비교했다. **3°는 급변 표시용 기준이지 제품 수용 임계값이 아니다.**

| 파일 / 블록 / 행(1부터) | 마커 회전 | 엔코더 변화 | 위치 변화 |
|---|---:|---:|---:|
| left_joint_A_axis_4 / 1 / 95→96 | 3.475° | 0.338° | 0.565mm |
| left_joint_B_axis_6 / 1 / 96→97 | 3.321° | 0.0909° | 0.582mm |
| left_marker_axis_4 / 1 / 14→15 | 3.458° | 0.4161° | 0.905mm |

3블록/3구간이 기준을 초과했다. 과거 보고서의 15블록/26구간과 다르지만 입력이 바뀌었으므로 특정 필터 수정의 개선 효과라고 단정하지 않는다. 현재 스윕 카메라 Z 범위는 **145.5~384.5mm**다.

Step2는 같은 팔 엔코더(모든 축 차이 <0.03°)의 44쌍씩을 비교했다. `inv(T_camera_right) @ T_camera_left`로 공통 카메라 움직임을 소거했다. 같은 표본이 여러 쌍에 사용되므로 44개의 독립 실험은 아니다.

| 데이터 | 상대 위치 변화 중앙값 / 최대 | 상대 회전 변화 중앙값 / 최대 |
|---|---:|---:|
| 10:05 | 0.128 / 0.357mm | 0.162 / 0.366° |
| 13:08 | 0.149 / 0.628mm | 0.127 / 0.318° |
| 16:05 | **0.396 / 0.954mm** | **0.195 / 0.410°** |

세 NPZ 모두 유한한 수치다. 최신 평균 관측에 다수의 수 도 단위 붕괴가 있다는 증거는 없으나, 위치 반복성은 오전보다 나쁘다. **“대체로 들어오지만 완전히 일정하거나 절대적으로 정확하다고 보증할 수 없음”**이 현재 판정이다. 공통 PnP 편향은 상대 비교에서 소거될 수 있다. 이미지·코너·프레임 시각·검출 실패 카운트가 없으므로 누락률, 일정 FPS, PnP 해 전환 원인은 확인할 수 없다.

Step1 브래킷 계산은 중간 프레임 회전을 기준으로 상대 회전축을 평균한다(`MarkerCalibrator.extract_axis_from_rotations`). 관측 회전 급변이 있으면 브래킷/J6에 영향을 줄 가능성은 있지만, 이번에는 그 영향량을 별도 재생하지 않았다. 이름에 `IPPE flip`이 있는 로그만으로 IPPE가 원인이라고 확정하지 않는다.

## 5. 테스트 복원·scratch 대체 및 수정 기준

백업 브랜치 `backup_twisted_20260910`의 `ccfd791`에서 `tests/` 18파일을 확인했다. 현재 없는 서비스 API를 필요로 하므로 통째로 복원하지 않았다. 헤드 SE(3) 보존과 Step1 반복기 수렴이라는 검증 목적을 현재 API로 이식했다. [테스트 사용법과 매핑](../../tests/README.md), [scratch 사용 전환 안내](../../scratch/README.md).

실행한 모듈 검증은 **정확히 2개, 둘 다 assertion 실패**다. import 오류나 장비 미연결 실패가 아니다. [실행 로그](module_tests.log). 제품 수정 전 회귀 기준으로 실패를 그대로 남겼다.

수정 우선순위:

1. J6 절대 목표를 상대 잔차로 변환한 뒤 감쇠 적용. 수렴 판정과 단계 간 결과 전달은 원시 잔차/실제 수렴을 기준으로 유지한다. 위 일정 목표 테스트가 −1° 수렴을 보장해야 한다.
2. Step1.5의 독립 물리 영점/유효 카메라 게이지 규약을 정리하고 회전·위치를 함께 처리한다. 품질 지표를 실제 3D 잔차와 구분한다. 위 고정 마커 보존 테스트를 통과해야 한다. 독립 기준 없이 Head Tilt만 강제 고정하지 않는다.

노션을 대조한 향후 기준과 상충사항은 [개발 지침](../../docs/calibration-development-guidelines.md)에 정리했다. 이번에는 사용자 요청의 **수정 전 분석과 검증 기준 마련**까지 수행했고, 두 제품 결함의 수정 및 실기체 재검증은 아직 하지 않았다.
